1. Project Background

The Singapore Real Estate Intelligence Platform helps a Singapore real estate agency make better pricing, rental, and customer-targeting decisions using ML. This workstream focuses on predicting monthly condominium rental prices and identifying key pricing factors.

Dataset: CondoRental.csv — 10,000 URA Executive Condominium rental transactions (postal districts 18–28), enriched with GPS coordinates and amenity distances via Singapore's OneMap API.

Success Criteria: Materially lower MAE/RMSE than a naive district-average baseline, with an interpretable feature-importance ranking the agency can act on.

2. Data Understanding & Selection

The base dataset (Condo_Rental.csv) covers 10,000 Executive Condominium rental transactions across postal districts 18–28, enriched via OneMap with GPS coordinates and distance to the nearest MRT station, supermarket and school. A third enrichment, Building_Age_Years, is resolved via an OneMap address lookup combined with a web-search step ("Jigtech Search") for each project's TOP year — correcting an earlier approach that mistakenly used lease commencement date as a building-age proxy.

3. Data Preparation Highlights

  • GPS enrichment via OneMap API, with a completeness gate removing 3 of 10,000 rows (0.03%) missing postal/address/coordinate fields — bringing the working dataset to 9,997 rows.
  • Building age resolved via OneMap SLA address + an encrypted, audit-logged "Jigtech Search" web-search step (search queries and evidence are never shown in clear text; encrypted with a Fernet key held outside the notebook).
  • Nearest MRT/LRT (94 stations, open rail dataset), supermarket (23) and school (100) distances computed via a fully vectorised Haversine matrix.
  • Rent outliers flagged (not removed) via 1.5×IQR — bounds [$2,250, $5,850], flagging 290 of 9,997 rows (2.90%).

Feature Selection

SLA_Latitude/SLA_Longitude were replaced with a single interpretable Distance_from_CBD_KM feature (Haversine vs. Raffles Place). Correlation and Variance Inflation Factor (VIF) screening then reduced the 9-field candidate list to 8 final model features — dropping Floor_Area_SQM (r = 0.978 with Floor_Area_SQFT, a near-duplicate measurement with a weaker link to rent).

Model Design

Three regression approaches of increasing complexity were compared — Linear Regression (interpretable baseline), Random Forest (robust to non-linear interactions), and XGBoost (gradient-boosted trees for predictive accuracy) — each benchmarked against a naive district-average baseline. An 80/20 train-test split (fixed seed) fed a single scikit-learn pipeline combining median imputation (numeric) and one-hot encoding (categorical), avoiding data leakage.

XGBoost was selected as the best-performing model, reducing MAE by 18.5% versus the naive baseline. A 5-fold cross-validation re-check confirmed the same ranking (std. dev. of only $7–$9 across folds), and GridSearchCV tuning was applied to all three model families — but for every family the untuned default beat the tuned version on real held-out test data, so the pre-tuning XGBoost model (MAE $456, RMSE $622, R² 0.352) was kept as final.

Recommendations by Stakeholder

LandlordsAnchor asking rent to predicted rent ± the MAE band ($456), not gut feel. Bedroom-count upgrades carry the most pricing leverage; treat location (MRT/supermarket proximity, CBD distance) and building age as secondary levers.
AgenciesScreen every listing pre-publication and flag asking rents outside the MAE band; use price-per-sqft vs. MRT-distance analysis to back pricing claims with data, and retain the amenity-source audit trail for verifiability.

Limitations & Future Work

At R² ≈ 0.35, the majority of rent variance remains unexplained — a genuine data ceiling (max correlation r = 0.31 for Floor_Area_SQFT; URA's privacy-banding of floor area/lease dates; no unit-quality signals like condition, floor level or view), not a modelling flaw. Concrete next steps: unit-level condition scores, floor level/facing direction, seasonal/temporal features, and targeted data collection in thin districts (24, 25, 28).

AI Ethics — Additional Notes

Building on the ethics table above: fallback GPS/amenity values should be routed to manual agent review before being quoted to a client rather than treated as equally trustworthy as live data, and the feature-importance ranking plus MAE confidence band should be surfaced directly alongside every predicted rent in deployment.
